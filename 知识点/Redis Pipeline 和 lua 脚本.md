
| 能力       | Pipeline      | Lua 脚本                  |
| -------- | ------------- | ----------------------- |
| 批量发命令    | ✅ 纯粹打包        | ✅ 脚本里随意写                |
| 命令结果复用   | ❌ 后命令拿不到前命令结果 | ✅ 可随意 `redis.call()` 复用 |
| 条件/循环/分支 | ❌ 无           | ✅ 完整 Lua 语法             |
| 复杂计算     | ❌ 只能客户端自己做    | ✅ 脚本内直接算                |
只要业务中出现“先读后写、if/else”等逻辑，只能够使用 lua 脚本。

## 原子性
| 指标  | Pipeline             | Lua 脚本                      |
| --- | -------------------- | --------------------------- |
| 原子性 | ❌ 不保证；命令序列可能被其他客户端打断 | ✅ 整个脚本**串行执行**，中途不会插入任何其他命令 |
| 回滚  | ❌ 失败命令之前已成功的不会回滚     | ❌ 同样无回滚，但**脚本内出现错误可中断后续命令** |

## 性能
| 场景      | Pipeline         | Lua 脚本                  |
| ------- | ---------------- | ----------------------- |
| 纯批量无逻辑  | 1 次 RTT，**网络最优** | 1 次 RTT，但脚本编译有微小开销      |
| 有依赖/需判断 | 做不到，必须多次往返       | **一次往返**搞定，实测可快 10-40 倍 |
| 高频小命令   | 吞吐量最高            | 略低（脚本缓存后差距<5%）          |
纯 batch 插入或查询，使用 Pipeline
需要判断以及依赖，使用 lua

## 应用场景
| 场景                      | 选型       | 理由                        |
| ----------------------- | -------- | ------------------------- |
| 批量写缓存（无逻辑）              | Pipeline | 网络 RTT 最少                 |
| 库存扣减：先 get 再 set，余额不足不扣 | Lua 脚本   | 原子判断+写，不会超卖               |
| 订单 30 min 未支付关闭         | Lua 脚本   | 读状态→改状态→写 Redis+MQ，一次原子完成 |
| 简单计数器批量 +1              | Pipeline | 无依赖，纯批量                   |
| 限流：先读当前次数，再决定是否放行       | Lua 脚本   | 避免竞态，100 ms→4 s 差距        |
