**Macvlan 允许容器绕过 Docker 的 NAT，直接连接到物理网络，使其表现得就像一台独立的物理机。**

macvlan使用场景：
1. 需要固定IP
2. 网络性能要求高：绕过Docker NAT和端口映射，网络路径更短，数据包转发开销更小，可以获得接近物理机性能的网络吞吐和更低的延迟
3. 避免端口冲突

工作原理：
内核级别的技术。
1. 选择一个父接口Parent Interface，在宿主机上选择一个网络接口作为父接口
2. 创建虚拟子接口，创建macvlan网络，docker会在内核层面基于这个父接口创建多个虚拟网络接口
3. 一对一绑定：每当一个容器加入macvlan网络，docker就会将其中一个虚拟接口分配给容器。虚拟接口拥有自己独立的mac地址
4. 直接通信：容器所有网络流量会通过虚拟接口，直接发送到物理网络上

关键限制和注意事项：
==宿主机无法与Macvlan容器直接通信。==
默认情况下，宿主机（比如IP为 192.168.1.10）**无法** ping 通或访问它自己创建的Macvlan容器（192.168.1.205）。
原因：这是由Linux内核的转发规则决定的。从宿主机发出的流量会通过父接口 eth0 直接出去，它“不知道”目标IP其实是在 eth0 的一个虚拟子接口上，因此流量无法正确返回。
解决方案：为宿主机也创建一个Macvlan虚拟接口，让宿主机通过这个新接口来与容器通信。
```shell
# 1. 创建一个新的Macvlan虚拟网卡，名为 macvlan-host
ip link add macvlan-host link eth0 type macvlan mode bridge

# 2. 为这个新网卡分配一个当前子网中未被使用的IP
ip addr add 192.168.1.220/24 dev macvlan-host

# 3. 启用这个网卡
ip link set macvlan-host up
```
宿主机就有了一个新的IP 192.168.1.220。现在，**宿主机可以通过这个IP与所有Macvlan容器通信了**，而容器也可以通过这个IP访问宿主机。

==云上无法配置Macvlan网络==
Macvlan配置需要父接口处于混杂模式（Promiscuous Mode），以便能接收发往不同MAC地址（即容器的MAC地址）的数据包。
但是云服务器一般无法修改网卡mode。

| 特性        | Bridge Network (默认)       | Macvlan Network             |
| --------- | ------------------------- | --------------------------- |
| **IP地址**  | 内部私有IP (e.g., 172.17.0.x) | 物理局域网IP (e.g., 192.168.1.x) |
| **网络模型**  | NAT + 端口映射                | 直接连接，无NAT                   |
| **性能**    | 有损耗                       | 接近物理机性能                     |
| **端口使用**  | 需映射，易冲突                   | 独立IP，无冲突                    |
| **网络可见性** | 容器对外部网络“不可见”              | 容器是物理网络上的“一等公民”             |
| **宿主机通信** | 简单直接                      | **默认不通，需要额外配置**             |
