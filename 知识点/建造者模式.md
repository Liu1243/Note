创建一个复杂的对象，例如HttpClient需要有很多的配置项：
- method (GET/POST, 必需)
- url (必需)
- username (可选)
- password (可选)
- connectTimeout (可选, 有默认值)
- readTimeout (可选, 有默认值)
- headers (可选)

创建这个对象时，有很多的方式进行：
方式一：伸缩构造器
```java
public class HttpClient {
    public HttpClient(String method, String url) { ... }
    public HttpClient(String method, String url, String username, String password) { ... }
    public HttpClient(String method, String url, String username, String password, int connectTimeout) { ... }
    // ... 噩梦开始了
}

// 使用时
HttpClient client = new HttpClient("POST", "http://example.com", null, null, 5000); // null是什么意思？代码可读性极差
```
构造函数爆炸多

方式二：JavaBean模式 Setter
```java
public class HttpClient {
    private String method;
    private String url;
    // ...
    public void setMethod(String method) { this.method = method; }
    // ...
}

// 使用时
HttpClient client = new HttpClient();
client.setMethod("POST");
client.setUrl("http://example.com");
client.setConnectTimeout(5000);
```
对象状态不一致：在所有setter调用完成之前，client处于不完整的状态；
非原子型创建
可变形：对象创建后仍然可以被修改

方式三：建造者模式
```java
public final class HttpClient { // 1. 主类，通常是不可变的 (final)

    private final String method;
    private final String url;
    private final String username;
    private final String password;
    private final int connectTimeout;
    private final int readTimeout;

    // 2. 私有构造函数，只能被Builder调用
    private HttpClient(HttpClientBuilder builder) {
        this.method = builder.method;
        this.url = builder.url;
        this.username = builder.username;
        this.password = builder.password;
        this.connectTimeout = builder.connectTimeout;
        this.readTimeout = builder.readTimeout;
    }

    // 3. 提供一个静态方法作为入口
    public static HttpClientBuilder builder() {
        return new HttpClientBuilder();
    }

    // 4. 静态内部Builder类
    public static class HttpClientBuilder {
        private String method;
        private String url;
        private String username;
        private String password;
        private int connectTimeout = 10000; // 可以设置默认值
        private int readTimeout = 10000;

        // 5. 流式API (Fluent API)，返回this
        public HttpClientBuilder method(String method) {
            this.method = method;
            return this;
        }

        public HttpClientBuilder url(String url) {
            this.url = url;
            return this;
        }
        
        // ... 其他属性的设置方法 ...

        // 6. 最终的build方法，返回一个完整的外部类实例
        public HttpClient build() {
            // 可以在这里进行参数校验
            if (method == null || url == null) {
                throw new IllegalStateException("Method and URL are required.");
            }
            return new HttpClient(this);
        }
    }
}
```

Lombok的@Builder注解自动实现建造者模式
```java
import lombok.Builder;

@Builder
public class HttpClient {
    private final String method;
    private final String url;
    private final String username;
    private final String password;
    @Builder.Default // 可以用这个注解设置默认值
    private int connectTimeout = 10000;
    @Builder.Default
    private int readTimeout = 10000;
}
```

经常会遇到@Builder和@Data一起使用的情况，这会产生什么问题呢？
**它们一起使用是有效的，但通常不是最佳实践，因为它会创建一个可以通过Builder模式构建的、但同时又是可变的对象。**

@Data是一个组合注解，包含五个注解的功能：
- @Getter: 为所有字段生成getter方法。
    
- @Setter: 为所有非final字段生成setter方法。
    
- @ToString: 生成一个toString()方法。
    
- @EqualsAndHashCode: 生成equals()和hashCode()方法。
    
- @RequiredArgsConstructor: **生成一个包含所有final或@NonNull字段的构造函数。** 这是关键点！

@Builder **在外部类中生成一个“全参构造函数”（all-args constructor），这个构造函数接收Builder实例作为参数来初始化对象。**

Lombok需要决定生成哪个构造函数。
- @Data想要生成一个RequiredArgsConstructor，即 public User(String email) { ... }。
- @Builder想要生成一个全参构造函数，即 private User(String username, String email, int age) { ... } (或者是接收Builder的版本)。
==Lombok的解决策略是：@Builder的优先级更高==
但最大的问题还是可变性，建造者模式是要生成一个不可变的对象，@Data破坏了最佳实践

最佳实践是@Builder+@Value，创建不可变对象。
- @Value: 这是@Data的不可变版本。它会：
    
    - 将所有字段设为private final。
        
    - 生成@Getter, @ToString, @EqualsAndHashCode。
        
    - 生成一个@AllArgsConstructor。
        
    - **不会生成@Setter**。


| 组合                    | 结果        | 优点                               | 缺点/适用场景                                            |
| --------------------- | --------- | -------------------------------- | -------------------------------------------------- |
| **@Data + @Builder**  | **可变对象**  | 1. 可以链式构建。<br>2. 构建后仍可修改。        | **通常不推荐**。破坏了不可变性，可能导致混乱。适用于明确需要一个“可配置的、可变的”对象的场景。 |
| **@Value + @Builder** | **不可变对象** | 1. 链式构建，代码清晰。<br>2. 对象线程安全，状态稳定。 | 对象的任何修改都需要创建一个新实例。                                 |
