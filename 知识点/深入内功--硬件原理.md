## TLB
因为TLB并不是很大，只有4k，而且现在逻辑核又造成会有两个进程来共享。所以可能会有cache miss的情况出现。而且一旦TLB miss造成的后果可比物理地址cache miss后果要严重一些，最多可能需要进行5次内存IO才行。建议你先用上面的perf工具查看一下你的程序的TLB的miss情况，如果确实不命中率很高，那么Linux允许你使用大内存页，很多大牛包括PHP7作者鸟哥也这样建议。这样将会大大减少页表项的数量，所以自然也会降低TLB cache miss率。所要承担的代价就是会造成一定程度的内存浪费。在Linux里，大内存页默认是不开启的。
> 在 TLB 命中率较低的时候，可以开启大内存页，增加 TLB 命中概率，缺点就是会有一定程度的内存浪费

## 内存对齐底层原理
内存是由多个 chip 组成，每个 chip 内部由 8 个 bank 组成，构造如下图：
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/69e4ea565cf299c0246bff5a8fe55a51_MD5.jpeg)
每个 bank 是一个二维平面上的矩阵，矩阵中每一个元素中保存 1 个字节。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/288f3b3ddf4e16a0901b0999eed28190_MD5.jpeg)
**内存编址方式**
连续的地址0x0000-0x0007，实际上是位于8个bank中的，每一个bank只保存了一个字节。在物理上，他们并不连续。
原因是电路工作效率，内存中的 8 个 bank 可以并行工作，读取地址 0x0000-0x0007，每个 bank 工作一次就可以获取到；如果存在一个 bank 里，就只能串行读取，读取 8 次。
==内存对齐最最底层的原因是内存的IO是以8个字节64bit为单位进行的。==
如果要获取 0x0001-0x0008，只能够先把 0x0000-0x0007 取出来，再把 0x0008-0x0015 取出来，组合起来返回。CPU和内存IO的硬件限制导致没办法一次跨在两个数据宽度中间进行IO。
> 1. 编译和连接器会自动对齐内存，但不能做到完美
> 2. 高速缓存里的 Cache Line 是 64 字节，是内存 IO 单位的 8 倍

## 内存 IO 过程
内存由 chip 构成，每个 chip 内部是由 8 个 bank 组成。每个 bank 是一个二维平面上的矩阵，矩阵中每一个元素中都是保存了 1 个字节，也就是 8bit。
当 CPU 向内存请求数据的时候，内存芯片是 8 个 bank 并行工作，bank 定位到 row 地址后，将对应的 row copy 到row buffer，再根据 col 地址将对应的元素取出，8 个 bank 将数据拼接返回 64 bit 宽的数据给 CPU。

### 内存 IO 延迟
内存延迟一般是通过CL-tRCD-tRP-tRAS四个参数来标识的。
- CL(Column Address Latency）：发送一个列地址到内存与数据开始响应之间的周期数
- tRCD（Row Address to Column Address Delay）：打开一行内存并访问其中的列所需的最小时钟周期数
- tRP(Row Precharge Time)：发出预充电命令与打开下一行之间所需的最小时钟周期数。
- tRAS(Row Active Time)：行活动命令与发出预充电命令之间所需的最小时钟周期数。也就是对下一次预充电时间进行限制。
CL 是固定周期数，其他三个是最小周期，参数单位都是时钟周期为单位。现代内存都是时钟周期上下沿各传输一次数据，用 Speed/2 可以得出。
 > 假设内存频率为 1066MHz，则时钟周期的频率为 1066/2=533MHz，延迟周期为7-7-7-24。
 > 结论：
 > 随机 IO：需要tRP+tRCD+CL个时钟周期，7+7+7=21个周期。但是还有个tRAS的限制，两次行地址预充电不得小于24。所以我们得按24来计算，24*(1s/533Mhz) = 45ns
 > 顺序 IO：这种状况下只需要CL个时钟周期 7*(1s/533Mhz)=13ns

内存随机 IO 开销比顺序 IO高好几倍，所以 OS 会尽量让内存通过顺序 IO 的方式进行，关键就是 ==Cache Line==。CPU 会一次向内存索要 60 字节的数据放到 Cache 缓存起来。
用上面的例子就是：
随机请求 8 字节：耗时是 45ns
随机请求 64 字节：耗时是 45+7\*13=136ns

内存也支持 burst（突发传输）模式，这种模式下只传入一次row、col 地址，就命令内存返回该内存开头的连续字节数据，比如 64 字节。这种模式下，只有第一次的8字节需要真正的行列访问延迟，后面的7个字节可以直接按内存的数据频率给吐出来。

##  内存核心频率
内存条经常宣传的是工作频率，在 OS 里叫做 Speed，内存术语中叫做等效频率，频率越高，每秒钟内存 IO 吞吐量越大。
内存中还有一个最基本的频率叫做==核心频率==，是实际内存电路工作时的一个振荡频率，很大程度上影响内存的 IO 延迟。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/384fb74cee24cc4f5e13dd7ce27fb6f6_MD5.jpeg)
从 SDR 时代到现在 DDR4 时代，核心频率一直都在 133MHz-200MHz 之间。内存 Speed 实在核心频率的基础上，通过各种技术手段放大的。
- SDR （Single Data Rate SDRAM）时代：一个时钟脉冲只能在脉冲上沿传输数据，也被称为单倍数据传输率内存。这个时期的内存提升方法就是提升内存电路的核心频率。
- DDR 时代：核心频率到 200MHz 再提升的难度很大。所以在电路时钟周期内预取 2bit，输出的时候在上升期和下降期各传输一次数据，在核心频率不变的情况下，Speed 翻倍。
- DDR2 时代：同样是在上下沿各传一次数据，但将 Prefech 提升为 4，每个电路周期一次读取 4bit，DDR2 的 Speed 达到了核心频率的 4 倍
- DDR3 时代：上下沿各传一次数据，Prefech 提升为 8。
- DDR4 时代：预取的提升非常困难，Prefech 仍为 8.提出 Bank Group 设计，允许各个 Bank Group 独立启动读、写等动作。

> 内存中还有个概念是==IO 频率==，也叫做时钟频率。
> 就是将内存的 Speed 频率除 2。

内存真正的工作频率是核心频率，时钟频率和数据频率都是在核心频率的基础上，通过技术手段放大出来的。内存越新，放大的倍数越多。但其实这些放大手段都有一些局限性。比如你的内存数据存储并不连续，这时候DDR2、DDR3的数据预取对你帮助并不大。再比如你的进程数据都存在一个Bank Group里，你的进程内存IO就根本不会达到DDR4厂家宣传的速度。

## CPU 内存支持
下面是 Skylake 的 CPU 总体结构图：
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/caf3a8670bcaf8d8f1a0b17acb60d051_MD5.jpeg)
该 CPU 有两个内存控制器（IMC，Integrate Memory Controller）。每个内存控制器上有一个 DDR PHY，负责连接 DDR 内存和 IMC 的桥梁，负责把 IMC 发来的数据转换为符合 DDR 协议的信号，传输给内存颗粒，也负责把内存返回给 CPU 的数据还在能换成 IMC 认识的信号，最后交给 CPU 核来处理。
每个 DDR PHY 有 3 个 DDR4 channels，每个 channel 有两个内存插槽。
所以该代际 CPU 有 6 个 channel，最多支持插入 12 条内存条；每个内存通道可以独立工作，该 CPU 支持的内存数据频率是 2666MHz，现在是 64 位计算机，所以：
- 单通道内存带宽=2666MHz\*64bit=21.33GB/s
- 6 个 channel 的总带宽 =21.33GB/s\*6=128GB/s

### 内存条模块规格
DIMM 是双列直插内存模块，是现代最常用的内存条模块的规格，英文全名 Dual In-Line Memory Module。信号接触在金手指两侧，并且在 DIMM 条的边沿作为信号接触面。
SIMM（Single-Inline Memory Module），SIMM 的位宽是 32 位，这是 32 位机时代的产物。
**UDIMM：无缓冲双列直插内存模块**，是 Unbuffered DIMM 的缩写。地址和控制信号不经缓冲器，无需做任何时序调整，直接到达 DIMM 上的各个 DRAM 芯片。这种内存要求 CPU 到每个内存颗粒之间的传输距离相等，这样并行传输才有效。对制造工艺要求高，对内存容量和频率产生了限制。
**SO-DIMM：小外形模块**，是 Small Outline DIMM 的缩写。常用于笔记本电脑，宽度标准为 67.6mm。
**RDIMM：带寄存器双列直插模块**，是 Registered DIMM 的缩写。RDIMM 在内存条上加了一个寄存缓存器（RCD，Register Clock Driver）进行传输。控制器输出的地址和控制信号经过Register芯片寄存后输出到DRAM芯片。不需要 CPU 到内存颗粒的传输距离相等。
**LRDIMM：低负载双列直插内存模块**，是 Load Reduced DIMM 的缩写。LRDIMM 相比 RDIMM 在引入寄存缓存器 RCD 的基础上，又进一步引入了数据缓冲器 DB（Data Buffer）。引入数据缓冲器作用是缓冲来自内存控制器或内存颗粒的数据信号。实现了对地址、控制信号、数据的全缓冲。成本更高，但可以支持更大容量。
### ECC 内存
ECC 是一种内存专用的技术。它的英文全称是 “Error Checking and Correcting”，对应的中文名称就叫做“错误检查和纠正”。从它的名称中我们可以看出，ECC 不但能发现内存中的错误，而且还可以进行纠正。
ECC 内存主板上会额外添加一个内存颗粒专门负责检查错误并纠正错误。
CPU 每个 channel 支持同时支持 72 位的读写，其中 64 位是数据，另外 8 位用于 ECC 校验。
由于有额外的硬件引入。所以 ECC 内存的价格会比普通内存要贵一些，速度也会慢 2% 左右。

## 内存 Rank、位宽以及内存颗粒的内部结构
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/e286e8b370cf554259037b182870d6c2_MD5.jpeg)
内存条中每个黑色颗粒集市一个 Chip。在正面有着一串字符串标识`16 GB 2R\*8 PC4-3200AA-SE1-11`。
- 2R：表示内存有 2 个 Rank
- \*8：表示每个内存颗粒的位宽是 8bit

黑色内存颗粒是 Chip，Rank 是属于同一个组 Chip 的总和，这些 Chip 并行工作，共同组成一个 64bit 的数据，供 CPU 同时读取。
CPU 的 IMC 能够对同一个 Rank 的 Chip 进行读写操作，一个 channel 能够同时读写 64bit 数据（ECC 是 72bit）。

2R 后面的\*4表示每个内存颗粒的位宽是 4bit，因为 CPU 要同时读写 64bit 数据，所以：
- 位宽为 4，需要 16 个 Chip 组成一个 Rank
- 位宽 8，需要 6 个 Chip

### 内存颗粒 Chip 内部结构
Chip 内部是由 bank 组成的。
每个 bank 内部就是电容的行列矩阵结构。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/78199aa281087f6315a07996fa6e303a_MD5.jpeg)
每个方块元素就是内存管理的最小单位，内存颗粒位宽，有若干小电容。
- 对于 1 R * 16 的内存条，一个位宽有 16 个 bit 位
- 对于 2 R * 8 的内存条，一个位宽有 8 个 bit 位
但是 CPU 并不是请求一个 64bit，而是请求64 字节，一个 Cache Line 的大小，填充自己的 L1、L2、L3 缓存，对于内存就是一次 BurstIO，需要内存连续工作多次。为了节约地址线数量。一般每个二维矩阵元素中存储的数据要比位宽更大一些。

## 为什么服务器内存硬件硬件上Chip 多？
- 需要 ECC 功能，需要比普通内存多 1/8 的颗粒数来支持 ECC
- 需要 RCD 模块降低地址等控制信号干扰影响，将单条容量做到更大
- 需要 DB 模块降低数据信号干扰影响，进一步将单条容量提高

## ECC 内存工作原理
ECC 内存应用了海明码：
- 如果 64 比特数据中发生了单比特翻转的话，海明码不但能够发现发生了错误，还能够找到错误的位置并纠正。
- 如果发生了两个比特翻转，海明码只能够发现出了错误。但无法定位到具体的位置无法纠错，只能通过重传的方式来解决。
- 如果发生了 3 个或者以上的比特翻转的话，海明码就无能为力了。
在实际中，64bit 数据中 3 个或者更多 bit 同时发生翻转的概率非常低，海明码硬件实现性能损耗为 2%-3%；SSD 硬盘中采用的是支持多比特翻转校验和纠错的 LDPC 码。
