## Linux 进程是如何创建的
通过 fork 创建进程。
Linux 中对进程的表示：
使用 task_struct 表示
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/0ba3c7c969651f1b98b447aa72d83486_MD5.jpeg)
一个任务（进程或线程）的大概状态流转图如下：
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/55c32ec6e7dd9b280bc77f6f1c5ff1ad_MD5.jpeg)
task_struct 有两个相关进程 id 的字段，分别是 pid 和 tgid。
- pid 是Linux 标识每一个进程而分配给的唯一标识，对于没有创建线程的进程，pid 和 tgid 是相同的
- tgid 是线程用来表示属于哪一个进程的 id

Linux 所有进程通过进程数管理。OS 启动会创建 init 进程，其他进程都是这个 init 进程直接或间接创建的。
```
init-+-atd  
  |-cron  
  |-db2fmcd  
  |-db2syscr-+-db2fmp---4*[{db2fmp}]  
  |          |-db2fmp---3*[{db2fmp}]  
  |          |-db2sysc---13*[{db2sysc}]  
  |          |-3*[db2syscr]  
  |          |-db2vend  
  |          `-{db2syscr}  
  |-dbus-daemon
```
这颗进程数由 task_struct 下的 parent、children、sibling 等字段表示的。

进程调度优先级：
- static_prio: 用来保存静态优先级，可以调用 nice 系统直接来修改取值范围为 100~139
- rt_priority: 用来保存实时优先级,取值范围为 0~99
- prio: 用来保存动态优先级
- normal_prio: 它的值取决于静态优先级和调度策略

进程地址空间：
内存描述符 mm_struct( mm 代表的是 memory descriptor)，整个进程的虚拟地址空间是由他表示的。
进程在运行的时候，在用户态其所需要的代码，全局变量数据，以及 mmap 内存映射等全部都是通过 mm_struct 来进行内存查找和寻址的。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/1174fd0ac129c83a14b2d2393e4fb994_MD5.jpeg)
在内核内存区域，可以通过直接计算得出物理内存地址，并不需要复杂的页表计算。而且最重要的是所有内核进程、以及用户进程的内核态，这部分内存都是共享的。
另外要注意的是，mm（mm_struct）表示的是虚拟地址空间。而对于内核线程来说，是没有用户态的虚拟地址空间的。所以内核线程的 mm 的值是 null。

进程文件系统信息：
进程的文件位置等信息是由 fs_struct 来描述的
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/526aa27ec5c2438d60a6b9fee7dab8f1_MD5.jpeg)

进程打开的文件信息：
每个进程用一个 files_struct 结构来记录文件描述符的使用情况， 这个 files_struct 结构称为用户打开文件表。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/f2b62b1173502c9bb6f74b7a58dc9ad3_MD5.jpeg)
在数组元素中记录了当前进程打开的每一个文件的指针。这个文件是 Linux 中抽象的文件，可能是真的磁盘上的文件，也可能是一个 socket。

namespaces：
在 Linux 中，namespace 是用来隔离内核资源的方式。通过 namespace 可以让一些进程只能看到与自己相关的一部分资源，而另外一些进程也只能看到与它们自己相关的资源，这两拨进程根本就感觉不到对方的存在。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/f71bd459d7a440093ed22539de848fc4_MD5.jpeg)

### fork 系统调用
fork 在内核中是系统调用实现的
```cpp
//file:kernel/fork.c  
SYSCALL_DEFINE0(fork)  
{  
 return do_fork(SIGCHLD, 0, 0, NULL, NULL);  
}
```
这里调用 do_fork 传入的第一个参数是 flag 选项。创建新进程传入的是 SIGCHLD （子进程在终止后发送 SIGCHLD 信号通知父进程），并没有 CLONE_FS 等其他 flag，只有创建线程才会传入其他 flag。
在 do_fork 的实现中，核心是一个 copy_process 函数，它以拷贝父进程的方式来生成一个新的 task_struct 出来。
```cpp
//file:kernel/fork.c  
long do_fork(unsigned long clone_flags,  
    unsigned long stack_start,  
    unsigned long stack_size,  
    int __user *parent_tidptr,  
    int __user *child_tidptr)  
{  
 //复制一个 task_struct 出来  
 struct task_struct *p;  
 p = copy_process(clone_flags, stack_start, stack_size,  
    child_tidptr, NULL, trace);  
  
 //子任务加入到就绪队列中去，等待调度器调度  
 wake_up_new_task(p);  
 ...  
}
```
创建完毕后，调用 wake_up_new_task 将新创建的任务添加到就绪队列中，等待调度器调度执行。
copy_process 函数如下：
```cpp
//file:kernel/fork.c  
static struct task_struct *copy_process(...)  
{  
 //3.1 复制进程 task_struct 结构体  
 struct task_struct *p;  
 p = dup_task_struct(current);  
 ...  
  
 //3.2 拷贝 files_struct  
 retval = copy_files(clone_flags, p);  
  
 //3.3 拷贝 fs_struct  
 retval = copy_fs(clone_flags, p);  
  
 //3.4 拷贝 mm_struct  
 retval = copy_mm(clone_flags, p);  
  
 //3.5 拷贝进程的命名空间 nsproxy  
 retval = copy_namespaces(clone_flags, p);  
  
 //3.6 申请 pid && 设置进程号  
 pid = alloc_pid(p->nsproxy->pid_ns);  
 p->pid = pid_nr(pid);  
 p->tgid = p->pid;  
 if (clone_flags & CLONE_THREAD)  
  p->tgid = current->tgid;  
  
 ......  
}
```
copy_process 先是复制了一个新的 task_struct 出来，然后调用 copy_xxx 系列的函数对 task_struct 中的各种核心对象进行拷贝处理，还申请了 pid。

复制进程 task_struct 结构体：
dup_task_struct 时传入的参数是 current，它表示的是当前进程。在 dup_task_struct 里，会申请一个新的 task_struct 内核对象，然后将当前进程复制给它。这里的 copy 是浅拷贝。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/c8152818525ddeeb1f332aa40fb105e5_MD5.jpeg)
```cpp
//file:kernel/fork.c  
static struct task_struct *dup_task_struct(struct task_struct *orig)  
{  
 //申请 task_struct 内核对象  
 tsk = alloc_task_struct_node(node);  
  
 //复制 task_struct  
 err = arch_dup_task_struct(tsk, orig);  
 ...  
}
```
alloc_task_struct_node 用于在 slab 内核内存管理区中申请一块内存出来。
申请完内存后，调用 arch_dup_task_struct 进行内存拷贝。

拷贝 files_struct：
进程之间是独立的，需要拷贝独立的 files 成员。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/9f893427cfc157c1accdf7428f69a3d2_MD5.jpeg)

拷贝 fs_struct：
与 copy files_struct 类似

拷贝 mm_struct：
地址空间是进程线程最核心的东西，每个进程都有独立的地址空间。
> 对于内核线程来讲，不需要虚拟地址空间，所以 mm 成员的值为 null。

拷贝进程命名空间 nsproxy：
默认创建进程没有指定命名空间标记，新旧进程独用同一套命名空间。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/d1c716357b34d6f5bf2fb3917a0cd3dc_MD5.jpeg)

申请 pid：
在 Linux 内部，为了节约内存，进程号是通过 bitmap 来管理的。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/6c937cd7892a871e57d33a16ee233543_MD5.jpeg)
在每一个 pid 命名空间内部，会有一个或者多个页面来作为 bitmap。其中每一个 bit 位（注意是 bit 位，不是字节）的 0 或者 1 的状态来表示当前序号的 pid 是否被占用。

进入就绪队列：
当 copy_process 执行完毕的时候，表示新进程的一个新的 task_struct 对象就创建出来了。接下来内核会调用 wake_up_new_task 将这个新创建出来的子进程添加到就绪队列中等待调度。


## Linux 中线程和进程的联系与区别
在 Linux 上，进程和线程的相同点要远远大于不同点。在 Linux 下的线程甚至都被称为了轻量级进程。
### 线程的创建方式
创建线程具体调用的是 pthread_create 函数，pthread_create 是在 glibc 库中实现的。在 glibc 库中，pthread_create 函数的实现调用路径是 __pthread_create_2_1 -> create_thread。其中 create_thread 这个函数比较重要，它设置了创建线程时使用的各种 flag 标记。
```cpp
//file:nptl/sysdeps/pthread/createthread.c  
static int  
create_thread (struct pthread *pd, ...)  
{  
 int clone_flags = (CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGNAL  
    | CLONE_SETTLS | CLONE_PARENT_SETTID  
    | CLONE_CHILD_CLEARTID | CLONE_SYSVSEM  
    | 0);  
  
 int res = do_clone (pd, attr, clone_flags, start_thread,  
      STACK_VARIABLES_ARGS, 1);  
 ...  
}
```
接下来的 do_clone 最终会调用一段汇编程序，在汇编里进入 clone 系统调用，之后会进入内核中进行处理。

### 内核对线程的表示
在 Linux 中，无论进程还是线程，都是抽象成了 task 任务，在源码里都是用 task_struct 结构来实现的。
不同线程 pid 不同，但属于同一进程的线程 tgid 相同。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/00f9add1a584a3123b7ed634c7ca1f56_MD5.jpeg)

### 线程创建过程
实际在底层实现上，最终使用的是同一个函数实现。
![](%E7%9F%A5%E8%AF%86%E7%82%B9/attachments/091c2596aca4bd767b1274ceebb0fb58_MD5.jpeg)
创建进程时**fork 函数调用 do_fork 的传的参数分别是SIGCHLD、0,0,NULL,NULL**。
do_fork 函数调用 copy_process 完成进程的创建。

线程创建会调用 pthread_create函数，调用到 clone 系统调用，传入一组 flag。
clone 系统调用的实现如下：
```cpp
//file:kernel/fork.c  
SYSCALL_DEFINE5(clone, ......)  
{  
 return do_fork(clone_flags, newsp, 0, parent_tidptr, child_tidptr);  
}
```
clone 系统调用会调用 do_fork，同样，do_fork 函数还是会执行到 copy_process 来完成实际的创建。

### 进程线程创建异同
**区别是二者在调用 do_fork 时传入的 clone_flags 里的标记不一样！**。
- 创建进程时的 flag：仅有一个 SIGCHLD
- 创建线程时的 flag：包括 CLONE_VM、CLONE_FS、CLONE_FILES、CLONE_SIGNAL、CLONE_SETTLS、CLONE_PARENT_SETTID、CLONE_CHILD_CLEARTID、CLONE_SYSVSEM。
CLONE_VM: 新 task 和父进程共享地址空间
CLONE_FS：新 task 和父进程共享文件系统信息
CLONE_FILES：新 task 和父进程共享文件描述符表

do_fork 系统调用见进程创建一节。里面会对 mm_struct、fs_struct、files_struct 以及 nsproxy 进行复制。
